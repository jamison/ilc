## 1. Baseline

Window `723-726` is not the lane-opening event. This artifact defines the
minimum post-launch conditions that would have to become true before any later
financial-shard opening-side governance work could be honest.

The current window therefore records later admissibility conditions rather than
claiming any of them are already satisfied.

## 2. Minimum trigger conditions

The minimum trigger conditions are:

1. public launch must already exist,
2. at least one public-launch monitoring cycle must have completed,
3. a concrete demand signal for sequestered financial-market activity must be
   visible,
4. contagion, firewall, and auditability prerequisites must already be
   specified,
5. the lane must still remain separate from `CDL-062`, ADR-0022/private-gated
   access hardening, and ordinary shard lifecycle.

## 3. Disqualifying conditions

The candidate remains disqualified if any of the following hold:

- public launch has not yet happened,
- no monitoring cycle exists yet,
- demand is speculative planning rhetoric rather than observed demand,
- `B_hft` is not separate from `B_e`,
- L1/L2 firewall conditions remain vague,
- the lane is being used to reopen private/gated access or ordinary
  shard-lifecycle questions by stealth.

Any one of these is enough to block honest opening-side work.

## 4. Monitoring evidence requirement

The required monitoring evidence is:

- at least one completed post-launch monitoring cycle,
- visible demand traces rather than abstract forecast,
- written evidence that market activity can remain sequestered,
- explicit failure-containment expectations for spillover and contagion,
- a written opening-side review showing that a new CDL is still actually
  needed rather than presumed.

No new CDL opening is recommended in the current window. Opening remains
deferred until the post-launch trigger and firewall package can be evidenced.
