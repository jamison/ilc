# ILC Cluster A Replay Proof Batch Report v0.1

## Overview
This specification defines the deterministic report format generated by the "verify-batch" operation for Cluster A replay proof packages. The report provides an aggregated view of validation results across multiple inputs, ensuring stable ordering and counters for reproducibility.

## Schema
See [ilc_cluster_a_replay_proof_batch_report_v0.1.json](./ilc_cluster_a_replay_proof_batch_report_v0.1.json) for the formal JSON Schema.

## Semantics

### Root Fields
- `report_version`: Must be `"v0.1"`.
- `total_packages`: Total number of input packages processed.
- `ok_count`: Number of packages that passed verification (`ok=true`).
- `fail_count`: Number of packages that failed verification (`ok=false`).
- `ok`: Boolean aggregation. True ONLY if `fail_count == 0`.
- `results`: List of individual result objects. **MUST** be sorted by `input_index`.
- `error_token_counts`: Map of error tokens to their occurrence count across all results. **Keys MUST be sorted lexicographically.**
- `batch_errors`: List of batch-level errors (e.g., manifest parsing issues, file read errors) that prevented individual package verification. **MUST be deterministically sorted.**

### Result Entry
- `input_index`: 0-based index reflecting the deterministic input order.
- `source_id`: The input identifier (e.g., relative file path from manifest or input directory).
- `ok`: Pass/Fail status for this specific package.
- `errors`: List of validation error tokens.
- `warnings`: List of validation warning tokens.
- `checks`: Deterministic list of check objects (passed through from the single-package verifier).
  - `check`: Check identifier string.
  - `status`: "pass" | "fail".
  - `error_code`: Error token string or null.

## Determinism Rules
1.  **Ordering:** The `results` array MUST preserve the order of inputs. The `error_token_counts` keys MUST be sorted lexicographically. `batch_errors` MUST be sorted lexicographically.
2.  **Formatting:** When serialized to canonical bytes, use compact separators (`","`, `":"`), sorted keys, and no trailing whitespace.
3.  **Source IDs:** Must be normalized relative paths to ensure portability across environments (no absolute paths).
